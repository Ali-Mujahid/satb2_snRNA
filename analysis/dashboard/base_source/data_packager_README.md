The data packager reads only completed native annotation/marker/plot outputs and saved UMAP/QC metadata. It writes the separate portable dashboard folder and does not extract nucleus RNA values, aggregate source RNA matrices or fit scientific models.

Run with the analysis v2 master configuration and `--outdir reports/offline_dashboard_v1`. A complete build packages 24 main frozen-cluster datasets, all 878 marker-panel stable IDs, pooled and WT statistics, and cKO descriptive statistics obtained by subtracting existing WT aggregate sums from existing pooled sums. Zero-denominator means/fractions remain missing. Native pooled/WT z references are retained; cKO z/reference remains unavailable. The build copies all 40 native plot books and completed technical/programme PDFs. `--assets-only` updates only PDF assets and manifest/receipt hashes after a closed base data build.

`data/manifest.js` registers `window.SATB2_DATA`. Every lazy classic-script shard registers `window.SATB2_SHARDS[id]` as gzip-base64 JSON. Coordinates sort stable nucleus IDs; `staging/DATASET_COORDINATE_INDEX.tsv.gz` supplies the exact zero-based deterministic mapping for the independently produced DE catalog. Main baseline coordinates contain only the final retained inference mask, while all original cluster audit records remain visible. The paired original/CellBender branches are distinct count sources even when their IDs coincide.

The full reviewed marker panel contains 147 supplied/canonical rows, 145 mapped rows and 139 unique stable IDs, with two unmapped AC129186.1 rows. The workbook-only subset is separately named (123 mapped rows and 117 unique IDs); representative marker presets supplement it. Physical layers remain undetermined and IN morphology headings remain expression programmes. No editable selection receives a cached fit without its exact source-bound membership/count-branch contract. Methods' `build_de_catalog.py` owns result/catalog shards; the frontend and final ZIP assembler are separate modules.

The JSON schema and source/asset bindings are in `schema_contract.json`, `DATA_BUNDLE_BASE_COMPLETE.json`, `data/manifest.json` and `data/asset_map.json`. Root performs independent produced-source/shard/index QA and browser checks before delivery. Synthetic scalar/null/stable-ID/classic-script gzip roundtrip checks passed before the actual build.
